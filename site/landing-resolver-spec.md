## 2. Resolver data (`site/resolver-data.json`, generated by the same script)

```json
{
  "works": [
    { "series": "pl", "vol": 139, "slug": "canones", "path": "/pl/139/canones/",
      "title": "Canones", "author": "Abbo of Fleury",
      "colFirst": 473, "colLast": 508,
      "anchors": ["473a","473b", "…all 83 anchor ids without the c prefix…"] },
    { "series": "pg", "vol": 139, "slug": "chronographia", "path": "/pg/139/chronographia/",
      "title": "Chronographia compendiaria", "author": "Joel",
      "colFirst": 223, "colLast": 288,
      "anchors": ["224","225","228", "…all 33…"] }
  ],
  "volumes": { "pl": { "1": {"scan": "<archive.org id>"}, "…all 221…" },
               "pg": { "…all 161 + note for 162…" } }
}
```

- Anchor lists: scrape `id="c…"` from the built work pages (source of truth for what's linkable).
- `volumes`: from `data/volumes.json` — one archive.org id per tome (first archive link; skip tomes with none). Keep the file small (~20–30KB is fine).
- PG 162 entry: `{"ghost": true}` — resolver shows the fire story instead of "not yet".

## 3. Resolver page (`site/resolve/index.html`)

Static page, self-contained JS (same look: bar + titlepage-ish heading; reuse site/styles.css).

Input: either a rewritten path (`location.pathname` = `/pl/139/473a`) or query params (`?s=pl&v=139&c=473a`). Parse: series ∈ {pl,pg}; vol = int; col = int + optional trailing letter a–d.

Resolution order:
1. Find a work in `resolver-data.json` with matching series+vol and `colFirst ≤ col ≤ colLast`.
2. **PL**: target anchor = `c{col}{letter}` if present in `anchors`; else nearest *preceding* anchor (compare numerically then by letter a<b<c<d); else the work path with no hash.
3. **PG spread normalization** (the Ordo-rerum-cites-the-Latin-column problem): a column pair is `pairOf(N) = Math.floor((N+1)/2)`; if `c{col}` is not in `anchors`, try the pair partner (`col±1` with the same pairOf); if neither, nearest preceding anchor. Joel's anchors are the GREEK columns only — a citation to 223 must land on `#c224`.
4. Redirect via `location.replace(path + '#' + anchor)`.
5. **Miss, volume exists**: render (no redirect): "PL 193, col 620 — not yet Englished." + one line: "The complete map exists; this work's page hasn't been built yet." + link to the volume's scan on archive.org + link home. If the vol is PG 162: the burned-volume story instead.
6. **Invalid** (bad series/vol out of range/unparsable): brief "not a Migne citation we recognize" + format examples.

## 4. `vercel.json` (repo root)

```json
{
  "rewrites": [
    { "source": "/pl/:vol(\\d{1,3})/:col(\\d{1,4}[a-dA-D]?)", "destination": "/resolve/" },
    { "source": "/pg/:vol(\\d{1,3})/:col(\\d{1,4}[a-dA-D]?)", "destination": "/resolve/" }
  ]
}
```
Filesystem wins before rewrites on Vercel, so `/pl/139/canones/` (real dir) is unaffected; the `\d`-anchored col pattern can't match slugs anyway. The deploy root is `site/` — when Wilson deploys: `cd site && npx vercel` (project not created yet; see hard stops).

## 5. Nearest-anchor fallback on work pages

Both builders append a ~10-line inline script to each work page: on `DOMContentLoaded`, if `location.hash` is set and `document.querySelector(hash)` is null, walk: strip letter → try `#c{col}` … then decrement col (down to colFirst) trying (for PL) letters d→a, until an existing anchor is found; then scroll to it. This makes deep links robust even if the resolver's data drifts from a rebuilt page. Rebuild both pages after editing the builders and re-run `verify-english*` (chunks untouched, but keep the habit).
